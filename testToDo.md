# План тестов конфигурации resourceReplacement

Предлагаемые сценарии для `useMarkdownEditor`. Это план: новые тесты пока не добавляются.
Перед реализацией сверить существующее покрытие — часть проверок отсутствующих опций
и передачи clipboard-метаданных уже есть.

Сценарии проверять в обоих режимах: ProseMirror (`wysiwyg`) и CodeMirror (`markup`).
Для переноса контента проверить направления PM → PM, PM → CM, CM → PM и CM → CM,
где различие режимов может повлиять на результат. Полное декартово произведение
всех опций не требуется: важны отдельные варианты и их значимые сочетания.

## Приоритеты

1. Матрица ID и `allowSameOrigin`.
2. Смешанный список ресурсов и выбор обрабатываемых типов.
3. Независимость настроек нескольких редакторов.
4. Триггеры, необязательные опции и жизненный цикл хука.
5. Расширяемость и ошибки конфигурации.

## Включение и минимальная конфигурация

- [ ] `resourceReplacement` отсутствует.
- [ ] `resourceReplacement: {}`.
- [ ] Есть `resources` и `triggers`, но нет `resolve`.
- [ ] Есть только `onChange`, без `resolve`.

Ожидание: обычная вставка работает, операции замены и события `onChange` не появляются.

- [ ] Есть `resolve`, но `resources` отсутствует.
- [ ] Есть `resolve`, но `resources: {}`.
- [ ] Есть `resolve` и ресурсы, но `triggers` отсутствует.
- [ ] Есть `resolve` и ресурсы, но `triggers: []`.

Ожидание: замена не запускается, исходные URL сохраняются.

- [ ] Есть рабочая конфигурация с `resolve`, но без `onChange`.

Ожидание: замена выполняется без обязательного подписчика на статусы.

## Выбор и описание ресурсов

Во вставке смешать изображения, файлы YFM и обычные ссылки.

- [ ] Включены только изображения.
- [ ] Включены только файлы.
- [ ] Включены оба типа.
- [ ] Один тип явно отключён через `false`.

Ожидание: resolver получает только выбранные ресурсы; остальные URL не меняются.

- [ ] Для ресурса задан собственный `kind` — он передаётся в resolver и используется для сопоставления ответа.
- [ ] `nameAttribute` отсутствует — ресурс обрабатывается без `name`.
- [ ] Два типа имеют одинаковый URL, но разные `kind` — замены независимы.

## Матрица ID и политики источника

| ID источника | ID получателя | Политика | Ожидание |
| --- | --- | --- | --- |
| Отсутствует | Отсутствует | По умолчанию | `source` отсутствует, замена разрешена |
| Есть | Отсутствует | По умолчанию | `source` отсутствует, замена разрешена |
| Отсутствует | Есть | По умолчанию | `source` отсутствует, замена разрешена |
| Есть | Другой ID | По умолчанию | `source.sameEditor: false`, замена разрешена |
| Есть | Совпадающий ID | По умолчанию | Замена пропускается |
| Есть | Совпадающий ID | `allowSameOrigin: false` | Замена пропускается |
| Есть | Совпадающий ID | `allowSameOrigin: true` | Resolver получает `source.sameEditor: true` |

- [ ] Проверить все строки матрицы.
- [ ] Для совпадающих ID отдельно проверить копирование внутри одного экземпляра редактора.
- [ ] Для совпадающих ID отдельно проверить два разных экземпляра с одинаковым `id`.
- [ ] При пропуске замены контент вставляется, но `resolve`, `onChange` и pending-операции не появляются.
- [ ] Без переданного `id` редактор не генерирует его автоматически и не записывает собственный ID в clipboard.
- [ ] Источник без `resourceReplacement`, но с `id`, всё равно записывает метаданные копирования.
- [ ] Последовательные вставки из своего, чужого и неизвестного источника не переиспользуют контекст предыдущей вставки.

В текущем контракте идентичность источника определяется совпадением ID, а не
равенством экземпляров редактора или доменов URL.

## Триггеры

Для каждой конфигурации выполнить и paste, и drop.

- [ ] `triggers: ['paste']` — замена запускается только для paste.
- [ ] `triggers: ['drop']` — замена запускается только для drop.
- [ ] `triggers: ['paste', 'drop']` — замена запускается для обеих операций.
- [ ] `'paste'`, `{name: 'paste'}` и `{name: 'paste', allowSameOrigin: false}` эквивалентны.
- [ ] Аналогичные строковая и объектные формы эквивалентны для `drop`.
- [ ] Для paste разрешён `allowSameOrigin`, для drop запрещён — политика применяется отдельно к каждому триггеру.

Реальный drag-and-drop между редакторами нужен как отдельный браузерный сценарий:
проверка того, что `['drop']` игнорирует paste, не подтверждает работу самого drop.

## Таймаут

- [ ] Без `timeoutMs` используется значение по умолчанию — 120 000 мс.
- [ ] Пользовательское положительное конечное значение применяется к операции.
- [ ] Ответ до таймаута применяется успешно.
- [ ] После таймаута сигнал отменён, операция завершена с ошибкой, поздний ответ игнорируется.
- [ ] Некорректные значения (`0`, отрицательное число, `NaN`, `Infinity`) отклоняются согласно контракту.

## Независимость экземпляров

- [ ] У двух редакторов разные списки ресурсов — каждый обрабатывает только свой список.
- [ ] У двух редакторов разные триггеры и `allowSameOrigin` — политики не смешиваются.
- [ ] У двух редакторов разные таймауты — завершение одного запроса не влияет на другой.
- [ ] У одного редактора замена отключена, у другого включена — копирование между ними работает согласно настройкам получателя.

## Жизненный цикл useMarkdownEditor

- [ ] Props изменены без изменения `deps` — существующий экземпляр и его исходная конфигурация сохраняются.
- [ ] Props и `deps` изменены — создаётся новый экземпляр с новой конфигурацией.
- [ ] При пересоздании старые pending-запросы отменяются; поздние ответы не меняют новый редактор.
- [ ] Изменение `id` при пересоздании учитывается в новых clipboard-метаданных и политике источника.

## Директивы, пользовательские обработчики и ошибки

- [ ] Замена файлов вместе с `experimental.directiveSyntax.yfmFile: 'disabled'`: обрабатывается legacy-форма.
- [ ] Режим `'enabled'`: обрабатываются legacy- и директивная формы.
- [ ] Режим `'only'`: обрабатывается только директивная форма.
- [ ] Неизвестное имя узла в `resourceReplacement.resources` вызывает понятную ошибку конфигурации.
- [ ] Неверный URL-атрибут вызывает понятную ошибку; другой атрибут не заменяется случайно.
- [ ] Для настроенного ресурса отсутствует подходящий CM-обработчик — ошибка содержит имя узла и URL-атрибут.
- [ ] Пользовательский обработчик в `markupConfig.extensions` переопределяет встроенный.
