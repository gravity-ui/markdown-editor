# Замена ресурсов при вставке

`resourceReplacement` позволяет приложению скопировать ресурсы вставленного Markdown
и вернуть новые значения. Загрузка бинарных файлов остаётся отдельным механизмом.

## Подключение через useMarkdownEditor

```tsx
const editor = useMarkdownEditor({
    initial: {mode: 'markup'},
    resourceReplacement: {
        resources: {
            image: {kind: 'image', valueAttribute: 'src', nameAttribute: 'alt'},
            yfm_file: {kind: 'file', valueAttribute: 'href', nameAttribute: 'download'},
        },
        triggers: ['paste', 'drop'],
        async resolve(resources, {operationId, signal}) {
            return copyResources(resources, {operationId, signal});
        },
    },
});
```

`copyResources` — функция приложения. Запрос содержит `{kind, value, name?}`, ответ —
`{replacements: [{kind, oldValue, newValue}]}`. Старые имена `path`, `oldPath`,
`newPath` и `urlAttribute` не поддерживаются.

Настройки парсера дополнительно передавать не нужно. Preset, `md`,
`wysiwygConfig.extensions`, directive syntax, PM transformers и модификаторы образуют
общую конфигурацию обоих режимов. Схема, парсеры и сериализатор готовятся лениво,
без PM-плагинов и EditorView, без переключения режима и отображения WYSIWYG.
При открытии WYSIWYG те же зависимости переиспользуются.

Wiki и Yjs не требуются. Wiki расширяет обычную конфигурацию редактора, включая
WikiGrid, Drawio, Include и другие включённые расширения. Отдельного списка
расширений для замены ресурсов нет. Работа с DOM должна оставаться в фабриках
плагинов и представлений, а не в регистрации расширений.

## Описания ресурсов

Ключ `resources` — имя PM-узла. `kind` — категория приложения, `valueAttribute` —
строковый атрибут, `nameAttribute` — необязательная подпись. Неуказанные типы и
значения `false` отключены. Пустые `resources` или `triggers` выключают интеграцию.

Для пользовательских URL укажите `valueType: 'url'`. Встроенные `image/src` и
`yfm_file/href` используют URL-правила автоматически. Остальные значения —
непрозрачные строки: без trim, смены регистра и URL-нормализации. Например:

```ts
resources: {
    asset: {kind: 'asset', valueAttribute: 'id'},
    video: {kind: 'video', valueAttribute: 'src', valueType: 'url'},
}
```

Оба узла должны быть зарегистрированы обычными расширениями с `spec`, `fromMd`
и `toMd`. Их парсер и сериализатор отвечают за синтаксис и корректное экранирование.
API `codeMirrorResourceSupport` и его типы удалены: отдельный CM-обработчик больше
не нужен. Пользовательскую грамматику для подсветки можно по-прежнему подключать
как языковое расширение; она не участвует в замене ресурсов.

## Поведение CodeMirror

После принятия paste/drop добавленный текст из транзакции разбирается общим
Markdown → PM парсером. Каждый независимый фрагмент разбирается отдельно, все
кандидаты одной транзакции передаются в один `resolve`. Shift не отключает сбор.

Этот сбор приблизительный: вставка изображения внутрь существующего блока кода
может отправить кандидата в `resolve`. Ссылочное изображение без определения
в самом фрагменте может не попасть в запрос. Карта исходных позиций не строится.

Во время ожидания весь Markdown, включая ресурсы, можно редактировать и удалять.
Лоадеров, защищённых диапазонов и atomicRanges ресурсов нет. Локальные undo/redo
и смена режима заблокированы до завершения всех операций, включая промежуток
между принятием вставки и запуском запроса. Новая вставка может начать свой запрос.

После ответа редактор разбирает **актуальный документ целиком** и меняет все узлы,
совпавшие по точной паре `(kind, oldValue)`. Кодовые узлы/марки и обычные ссылки
исключаются. Затем документ сериализуется; форматирование может измениться,
ссылочные определения могут превратиться в inline-ссылки. Если атрибуты узлов
не изменились, документ вообще не переписывается.

В сериализованном Markdown символ `&` в URL изображения записывается как `&amp;`.
При разборе восстанавливается исходный URL: буквальные `&copy;` и `&#65;` остаются
частью адреса. Общий сериализатор применяет это правило и в WYSIWYG.

Следствие приблизительного сбора: кандидат из вставки внутри кода может вызвать
копирование на сервере и замену совпадающего ресурса вне кода. Сам код не меняется.

Участок между общим префиксом и суффиксом исходного и сериализованного текста
заменяется обычным CM-dispatch.
Результат входит в обычную историю: undo может восстановить прежние значения,
redo не вызывает повторный `resolve`. Специального исправления старой истории нет.

## Поведение ProseMirror

Сохраняется прежняя механика: вставленные ресурсы скрываются лоадерами и защищены
от редактирования и удаления, остальные части документа доступны для правок.
Результат меняет атрибуты всех текущих совпадений вне кода. Undo/redo вставки
сохраняют новые значения и не повторяют запрос. Замена ранее существовавшего ресурса
не отменяется вместе с вставкой. Более ранняя история может вернуть старое значение;
таблица нормализации всей истории не ведётся.

## Операции, ошибки и сохранение

Контроллер общий для двух режимов. Дубликаты внутри запроса объединяются по
`(kind, value)`. Пустой и частичный ответы успешны. Неизвестные пары, конфликтующие
замены и недопустимые URL приводят к ошибке. Замены одного ответа не каскадируют.
Все изменения готовятся до записи; ошибка преобразования не оставляет частичный результат.

Параллельные ответы применяются к текущему документу: первый ответ может убрать
совпадения для второго. Отмена одной операции не отменяет результат другой.

- `getPendingResourceReplacements()` возвращает незавершённые запросы с `operationId`.
- `cancelResourceReplacement(operationId)` отменяет один запрос.
- `onChange` получает `pending`, `succeeded`, `failed`, `cancelled`.
- `timeoutMs` необязателен; если задан, должен быть конечным положительным числом.
- Поздний ответ отменённой/завершённой операции игнорируется.
- При уничтожении редактора его контроллер отменяет операции.

До ответа документ содержит старые значения. Разрешать ли сохранение в этот момент,
решает приложение. Ошибка или отмена освобождают блокировки; в PM также исчезают лоадеры.

## Самостоятельный CodeMirror

Явно передайте зависимости из своей общей конфигурации расширений:

```ts
const {markupParser: parser, serializer} = extensionsManager.buildDeps();
const extension = codeMirrorResourceReplacement({
    parser,
    serializer,
    resources,
    controller,
    shouldTrack: (tr) => tr.isUserEvent('input.paste') || tr.isUserEvent('input.drop'),
    // escapeConfig: настройки сериализации при необходимости
});
```

`codeMirrorResourceReplacement` экспортируется из корня пакета. Менеджер можно
создать через `createEditorExtensions` из `@gravity-ui/markdown-editor/core`,
передав обычные расширения. Парсер без необходимых Specs не заменяет конфигурацию
редактора. Владелец самостоятельной интеграции уничтожает её контроллер.

## Wiki и Yjs

В resolve Wiki новые URL изображений предварительно загружаются через Image и decode().
До завершения прогрева операция остаётся pending, а PM-декоратор скрывает старую
картинку до применения замены. Повторяющиеся URL прогреваются один раз, файлы
не загружаются. Прогрев необязательный: ошибка загрузки или таймаут (10 секунд)
не мешают применить новый URL — изображение может загрузиться позже.
Отмена прерывает ожидание, очищает запросы изображений и предотвращает замену. Кэш прогревается только
в браузере инициатора; остальным участникам Yjs передаётся обычная замена URL.
Прогрев реализован в потребителе через существующий resolve, без дополнительного API редактора.

Wiki использует `createCollabMarkupConfig` с явным `UndoManager` и `yCollab`.
Стандартная CM-история отключена. Методы менеджера проверяют
`isCodeMirrorHistoryLocked(view.state)` **до изменения Y.Doc**. Защита охватывает
клавиатуру, `beforeinput` и прямые вызовы того же менеджера; действия других
участников не блокируются.

В `y-codemirror.next@0.3.5` входящие изменения имеют закрытую `ySyncAnnotation`.
Адаптер Wiki использует события наблюдения Y.Doc и origin, чтобы дополнительно
пометить их `Transaction.remote`. Исходные аннотации и origin binding сохраняются.
Такие изменения, включая доставленную через Yjs историю, не запускают `resolve`.

Результат проходит через активный CM и его binding в Y.Text. PM/Yjs-документ
WYSIWYG напрямую не изменяется. Используется обычная история Yjs, без исправления
старых событий. Владелец адаптера освобождает подписки и UndoManager даже если
Markdown-режим не был открыт.

В текущем подключении Wiki общий `createResourceReplacement` сохраняет существующий
демонстрационный resolver с задержкой и подстановочными URL для изображений и файлов.
Подключение серверного копирования и выбор дополнительных категорий ресурсов —
отдельная задача. Specs Wiki уже участвуют в разборе и сериализации всего документа.
