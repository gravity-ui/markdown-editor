# Промпт: обобщить ресурс с URL до строкового значения

Нужно обобщить resourceReplacement: ресурс может определяться не только URL, но и
непрозрачным строковым идентификатором.

Сначала прочитай AGENTS.md, codex.md и текущую реализацию. Тесты не запускай.
Учитывай изменения других чатов: недавно переносилась грамматика CodeMirror,
а RESOURCE_REPLACEMENT_TUTORIAL.md создаётся отдельно.

До изменения кода сначала предложи конкретный план, новый API подготовки значений и
состав коммита текущего состояния для точки возврата. Дождись согласования. После него
сначала сохрани согласованное исходное состояние коммитом, затем выполняй изменения.
Новые решения вне согласованного плана также обсуждай до реализации. Не включай
несвязанные изменения в коммит без разрешения и не выполняй push.

## Цель и контракт

Общий механизм операций не должен предполагать, что значение ресурса является URL.
Правила URL нужны только там, где значение действительно является адресом.
Произвольный id не нормализуется, не декодируется и не кодируется как URL.

Переименовать:

- ResourceDescription.urlAttribute → valueAttribute;
- ReplacementResource.path → value;
- oldPath/newPath в результате resolve → oldValue/newValue;
- ключ дедупликации и сопоставления — пара (kind, value).

name остаётся необязательной подписью. Значение остаётся строкой: поддержку объектов
и числовых идентификаторов добавлять не нужно.

```ts
resources: {
    asset: {
        kind: 'asset',
        valueAttribute: 'assetId',
        nameAttribute: 'title',
    },
}
```

Пример ресурса:

```ts
{kind: 'asset', value: 'asset:ABC/123', name: 'Схема'}
```

Пример результата:

```ts
{
    replacements: [{
        kind: 'asset',
        oldValue: 'asset:ABC/123',
        newValue: 'asset:XYZ/456',
    }],
}
```

## Требования

1. Оставить resources источником конфигурации. Настройка исключительно через внешние
   NodeSpec — отдельная задача и сюда не входит.
2. Обновить общий контроллер, типы, оба движка, публичные экспорты, примеры и существующие
   проверки, завязанные на прежние имена. Обновить fallback-подписи лоадеров с resource.path.
3. Сохранить проверки структуры ответа, принадлежности каждой пары исходному запросу
   и конфликтующих замен, а также требование непустого нового строкового значения.
   Идентификаторы сопоставлять точно, без trim, изменения регистра и URL-нормализации.
4. Убрать безусловную URL-валидацию из общего сбора и применения ресурсов. Для встроенных
   изображений и файлов сохранить действующие проверки URL, нормализацию и экранирование.
   Выбрать понятное место для этих правил в обработчиках/описаниях ресурсов без избыточной
   инфраструктуры. В PM не определять «это URL» только по имени атрибута или kind.
5. В CodeMirror обобщить контракт чтения и записи значения, включая urlAttribute,
   и оценить переименование urlRange в valueRange. Разделить непрозрачное значение и
   его текстовое представление. Подготовка записи должна учитывать конкретный синтаксис.
   Если id находится в кавычках, отсутствие URL-нормализации не отменяет корректного
   экранирования кавычек и других значимых символов.
6. Сохранить обработку ссылочных изображений: перевод их суффикса в inline-адрес без
   изменения общего определения ссылки.
7. В ProseMirror записывать значение в настроенный атрибут. Непрозрачный id сохраняется
   без URL-преобразований; настоящий URL проходит соответствующие проверки.
8. Подготавливать и проверять результат до dispatch. Ошибка не должна приводить к
   частично применённым заменам в документе.
9. Сохранить остальные требования codex.md: один resolve на вставку, дедупликация внутри
   операции, глобальная замена совпадений, исключение кода и обычных ссылок, лоадеры,
   защита, блокировка undo/redo и режима, прежние гарантии истории, отсутствие каскада,
   успех для пустого/частичного ответа, отмена, таймаут и игнорирование поздних результатов.

Не своди работу к механическому переименованию. Проверь все места normalizeLink,
validateLink, unescapeAll и URL-кодирования: id не должен проходить через них без явного
требования его синтаксиса.

Это намеренное изменение контракта. Не добавляй совместимость со старыми именами без
необходимости. Обнови документацию контракта. RESOURCE_REPLACEMENT_TUTORIAL.md не
перезаписывай, пока он обновляется в другом чате: отдельно перечисли нужные поправки.

Тесты не запускай. В конце опиши разделение между общим значением и сериализацией,
затронутый публичный API и фактически выполненные проверки.
