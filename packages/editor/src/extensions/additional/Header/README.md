# Header

Hero-блок страницы: заголовок, подзаголовок и до двух кнопок-действий поверх настраиваемого
оформления — размер, края, фон (цвет или картинка), рамка, декоративные узоры.

## Markdown

```
:::header [Добро пожаловать на портал] {format=large fill=green-light}
Всё, что нужно команде, — на одной странице.

::action[Начать работу]{href="/start"}
::action[Смотреть разделы]{href="/sections" variant=link}
:::
```

- Инлайн-контент директивы — заголовок, первый абзац — подзаголовок, `::action` — кнопки.
- Всё остальное внутри контейнера выносится **за** блок, а не теряется.
- В разметку попадают только не-дефолтные атрибуты, в фиксированном порядке.

## Атрибуты

| Ключ | Значения | Дефолт |
|------|----------|--------|
| `format` | `large` / `small` | `large` |
| `edges` | `rounded` / `bleed` | `rounded` |
| `bg` | `fill` / `image` | `fill` |
| `layout` | `cover` / `split` — только при `bg=image` | `cover` |
| `fill` | имя из палитры: `blue-light`, `green-light`, `yellow-light`, `red-light`, `purple-light`, `grey`, `blue`, `green`, `yellow`, `red`, `purple`, `dark` | `blue-light` |
| `text` | `auto` / `light` / `dark` | `auto` |
| `image` | URL картинки | `''` |
| `border` | `none` / `solid` / `dashed` / `dotted` | `none` |
| `blobs` | `true` / `false` | `true` |
| `seed` | число, `0` — курируемая раскладка | `0` |

У `::action` два атрибута: `href` и `variant` (`primary` / `normal` / `link`). Ссылку можно задать
и дестинацией: `::action[Текст](/start)`.

Неизвестное значение любого атрибута схлопывается в дефолт при парсинге — битая разметка из
чужого источника не доезжает ни до CSS, ни до сериализатора.

## Подключение

```ts
import {Header} from '@gravity-ui/markdown-editor/extensions/additional/Header';
import {wHeaderItemData} from '@gravity-ui/markdown-editor/extensions/additional/Header/toolbar';

useMarkdownEditor({
    wysiwygConfig: {
        extensions: (builder) => builder.use(Header, {fileUploadHandler}),
        extensionOptions: {
            commandMenu: {actions: wysiwygToolbarConfigs.wCommandMenuConfig.concat(wHeaderItemData)},
        },
    },
});
```

Расширение не входит ни в один пресет: блок тяжёлый, и платить за него должны только те, кто его
включает. `wHeaderItemData` гейтится через `e.actions.toHeader?.` — один и тот же конфиг тулбара
работает и без подключённого расширения.

### Опции

| Опция | Что делает |
|-------|------------|
| `fileUploadHandler` | Загрузчик картинки фона. Без него пункт «загрузить» в панели не показывается, но ссылку можно задать из markdown |
| `headerKey` | Хоткей вставки блока |

## Что внутри

- `HeaderSpecs/` — схема, парсер и сериализатор. Ни React, ни DOM: слой поднимается в SSR,
  в markup-режиме и в тестах.
- `HeaderSpecs/md/header.ts` — markdown-it плагин на `@diplodoc/directive`: контейнер `:::header`,
  leaf `::action` и core-правило, раскладывающее плоский поток токенов по слотам схемы.
- `HeaderSpecs/attrs.ts` — единственная точка нормализации и сериализации значений; её зовут
  и парсер директивы, и `parseDOM`, и команды панели.
- `HeaderSpecs/blobs.ts` — детерминированная геометрия узоров от `seed`.
- `commands.ts` — вставка, изменение атрибутов, кнопки и границы клавиатуры.
- `plugins/HeaderTooltipPlugin/` — плавающая панель настроек поверх блока.
- `plugins/active.ts` — декорация активного блока.

Нодвью нет намеренно: узоры и фон — чистые функции от атрибутов, поэтому их рисует `toDOM`.
Отсюда бесплатно берутся перерисовка при смене атрибута, копипаст и серверный рендер.

## Решения, которые стоит знать

**Цвет хранится именем токена, а не hex.** Документ переживает смену темы и ребрендинг без
миграции разметки. Палитра — одна SCSS-карта (`src/styles/yc-header-fill.scss`), развёрнутая
и в стили блока, и в сво́тчи панели, поэтому они не могут разойтись.

**Контраст текста — часть этой же карты, а не арифметика по яркости.** Каждая заливка знает
свою схему текста; `text=light|dark` перебивает её вручную — например для тёмной фотографии.

**Скрим над картинкой нейтральный, не окрашенный в заливку.** Иначе на стыке вуали и картинки,
фон которой не совпал с заливкой, видна вертикальная граница.

**Картинка масштабируется как `auto 100%`, а не `cover`.** Типовой hero — панорама 1200×340,
и `cover` в компактном формате срезает у иллюстраций верх и низ.

**Структура блока жёсткая** — `header_title header_subtitle header_actions`. «Непарных» состояний
не существует, поэтому и репарирующий `appendTransaction` не нужен.

## Ограничения

- В markup-режиме атрибуты правятся руками: конвейер загрузки файлов в CodeMirror умеет
  генерировать только `![](url)` и `{% file %}`.
- Вертикальный `bleed` (отрицательные поля до краёв колонки) — задача страницы-хоста: расширение
  снимает только скругление.
- Оформление не реагирует на саму картинку: тёмная иллюстрация требует явного `text=light`.
