# Header

Hero-блок страницы: заголовок, описание и до двух кнопок-действий поверх настраиваемого
оформления — размер, края, фон (цвет или картинка), рамка.

## Markdown

```
:::header-block {format=large fill=green}
title: 'Добро пожаловать на портал'
description: 'Всё, что нужно команде, — на одной странице.'
actions:
  - type: 'button'
    title: 'Начать работу'
    href: '/start'
  - type: 'link'
    title: 'Смотреть разделы'
    href: '/sections'
:::
```

- Оформление — в атрибутах директивы, содержимое — в теле, одним yaml-документом.
- Пустые ключи в разметку не попадают; значения всегда в кавычках.
- Внутри блока нет форматирования: ни жирного, ни курсива, ни ссылки в заголовке. Ссылка
  бывает только у кнопки, в `href`.

## Атрибуты

| Ключ     | Значения                                                                                 | Дефолт    |
| -------- | ---------------------------------------------------------------------------------------- | --------- |
| `format` | `large` / `small`                                                                        | `large`   |
| `edges`  | `rounded` / `bleed`                                                                      | `rounded` |
| `bg`     | `fill` / `image`                                                                         | `fill`    |
| `layout` | `cover` / `split` — только при `bg=image`                                                | `cover`   |
| `fill`   | имя из палитры: `grey`, `blue`, `green`, `yellow`, `orange`, `red`, `purple`, `contrast` | `blue`    |
| `text`   | `auto` / `light` / `dark`                                                                | `auto`    |
| `image`  | URL картинки                                                                             | `''`      |
| `border` | `none` / `solid` / `dashed` / `dotted`                                                   | `none`    |

## Тело

| Ключ                | Значения                     |
| ------------------- | ---------------------------- |
| `title`             | строка                       |
| `description`       | строка                       |
| `actions[].type`    | `button` / `link`            |
| `actions[].title`   | строка                       |
| `actions[].href`    | ссылка                       |

Неизвестное значение любого атрибута или типа кнопки схлопывается в дефолт при парсинге —
битая разметка из чужого источника не доезжает ни до CSS, ни до сериализатора. Сломанный yaml
даёт пустой блок, а не исключение.

## Подключение

```ts
import {Header} from '@gravity-ui/markdown-editor/extensions/additional/Header';
import {wHeaderItemData} from '@gravity-ui/markdown-editor/extensions/additional/Header/toolbar';

useMarkdownEditor({
  wysiwygConfig: {
    extensions: (builder) => builder.use(Header, {fileUploadHandler}),
    extensionOptions: {
      commandMenu: {actions: wysiwygToolbarConfigs.wCommandMenuConfig.concat(wHeaderItemData)},
    },
  },
});
```

Расширение не входит ни в один пресет: блок тяжёлый, и платить за него должны только те, кто его
включает. `wHeaderItemData` гейтится через `e.actions.toHeader?.` — один и тот же конфиг тулбара
работает и без подключённого расширения.

### Опции

| Опция               | Что делает                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `fileUploadHandler` | Загрузчик картинки фона. Без него пункт «загрузить» в панели не показывается, но ссылку можно задать из markdown |
| `headerKey`         | Хоткей вставки блока                                                                                             |

## Что внутри

- `HeaderSpecs/` — схема, парсер и сериализатор. Ни React, ни DOM: слой поднимается в SSR,
  в markup-режиме и в тестах.
- `HeaderSpecs/content.ts` — единственное место, которое знает формат тела директивы:
  разбор и печать yaml, нормализация кнопок.
- `HeaderSpecs/attrs.ts` — то же самое для атрибутов: её зовут и парсер директивы, и `parseDOM`,
  и команды панели.
- `HeaderSpecs/md/header.ts` — markdown-it плагин на `@diplodoc/directive`.
- `commands.ts` — вставка, изменение атрибутов, кнопки и границы клавиатуры.
- `plugins/HeaderTooltipPlugin/` — плавающая панель настроек поверх блока.
- `plugins/active.ts` — декорация активного блока.

Нодвью нет намеренно: оформление — чистая функция от атрибутов, поэтому его рисует `toDOM`.
Отсюда бесплатно берутся перерисовка при смене атрибута, копипаст и серверный рендер.

## Решения, которые стоит знать

**Содержимое — yaml в теле директивы, а не инлайн-контент.** Форматирования внутри блока нет,
значит хранить текст в markdown-разметке незачем — а платить за это пришлось бы разбором
`**` и `[]()` в заголовке. Слоты приезжают в документ одним токеном с `noCloseToken`, поэтому
`**жирный**` остаётся ровно теми символами, которыми его написали.

**В prosemirror слоты — обычные текстовые ноды** (`text*`, `marks: ''`) внутри контейнера,
с жёсткой структурой `title description actions`. «Непарных» состояний не существует, поэтому
и репарирующий `appendTransaction` не нужен.

**Значения yaml печатаются в кавычках всегда.** Заголовок — произвольный человеческий текст,
и без кавычек двоеточие, `#` или `-` в начале молча меняют структуру документа при следующем
чтении. Читается yaml с `JSON_SCHEMA`: иначе `yes` стал бы булевым, а `2020-01-01` — датой.

**Цвет хранится именем заливки, а не hex.** Документ переживает смену темы и ребрендинг без
миграции разметки. Палитра — одна SCSS-карта (`src/styles/yc-header-fill.scss`), развёрнутая
и в стили блока, и в сво́тчи панели, поэтому они не могут разойтись.

**Заливки собраны на `*-solid`-ступенях, а не на `--g-color-base-*-light`.** Семантические
светлые токены полупрозрачны (`base-info-light` — это `rgba(54,151,241,0.15)`) и рассчитаны
на подсветку строки: на поверхности в треть экрана вся палитра выглядит одинаково белёсой.

**Контраст текста задан ролью поверхности, а не статической парой цветов.** `*-solid`-токены
сами меняются по теме, поэтому каждая заливка объявляет `surface: normal | inverted`, а цвет
берётся из `--g-color-text-primary` или `--g-color-text-inverted-primary`. `text=light|dark`
перебивает это вручную — например для тёмной фотографии.

**Картинка растворяется в заливке маской, а не прикрывается вуалью.** Полупрозрачная вуаль
приглушает иллюстрацию, но оставляет вертикальный стык там, где её фон не совпал с заливкой;
`mask-image` убирает край совсем и заодно гарантирует, что текст всегда лежит на чистой заливке.
Отсюда же `cover`: гасить надо именно край картинки, а при вписывании по высоте он стоит там,
где придётся по пропорциям файла. Иллюстрациям, которым широкий кроп не идёт, есть `split`.

## Ограничения

- В markup-режиме тело правится руками: конвейер загрузки файлов в CodeMirror умеет
  генерировать только `![](url)` и `{% file %}`.
- Вертикальный `bleed` (отрицательные поля до краёв колонки) — задача страницы-хоста: расширение
  снимает только скругление.
- Оформление не реагирует на саму картинку: тёмная иллюстрация требует явного `text=light`.
- Незнакомые ключи тела и атрибуты директивы отбрасываются при парсинге, а не сохраняются.
  Документ, записанный более новой версией расширения, потеряет незнакомую настройку после
  «открыл — сохранил». Passthrough потребует отдельного хранилища для чужих ключей — решение
  отложено осознанно.
- Заголовок блока не прорастает в заголовок страницы: у редактора нет канала, через который
  хост узнал бы о нём. Это следующий шаг, а не свойство текущей версии.
