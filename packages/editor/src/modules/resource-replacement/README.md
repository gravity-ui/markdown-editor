# Замена ресурсов

Публичное подключение и правила движков описаны в
[руководстве](../../../../../docs/how-to-resolve-pasted-resources.md), границы модулей —
в [архитектуре](../../../../../docs/pasted-resources-architecture.md).

- `controller.ts` управляет запросами двух режимов, не зависит от DOM и React.
- `controller.utils.ts` дедуплицирует точные `(kind, value)` и проверяет ответ.
- `markdown.ts` разбирает Markdown настроенным парсером, собирает ресурсы,
  заменяет атрибуты PM-узлов и сериализует. Не зависит от dispatch, resolve и истории.
- `codemirror/` получает принятые paste/drop, хранит идентификаторы операций,
  вызывает контроллер и заменяет изменившийся участок актуального документа.
- `prosemirror/` сохраняет прежние диапазоны, лоадеры, защиту и историю вставки.
- `trigger-policy/` выбирает разрешённые события; бинарная загрузка отдельна.
- `urls.ts` отличает URL от непрозрачных ID по описанию узла и атрибута.

В CodeMirror нет ресурсных лоадеров и защищённых диапазонов. Сбор отдельных вставленных
фрагментов приблизительный; применение разбирает весь текущий документ. Если узлы
не изменились, сериализации нет. Иначе полная сериализация применяется одной заменой между общим префиксом и суффиксом
через обычную историю: undo может вернуть старые значения. Новый resolve не запускается
для undo/redo, remote-транзакций и служебного применения ответа.

`useMarkdownEditor` передаёт общие parser/serializer автоматически. buildDeps готовит
их без WYSIWYG-плагинов и EditorView. Wiki и Yjs не нужны. Самостоятельная интеграция
явно предоставляет parser, serializer, resources, controller и shouldTrack.

Для внешней истории экспортируется isCodeMirrorHistoryLocked(state). Проверку следует
делать до изменения внешнего документа. В Wiki так защищены методы менеджера Yjs,
который передан в yCollab; там же входящие синхронизации помечаются Transaction.remote.

Контроллер сохраняет параллельные запросы, валидацию, частичные/пустые ответы, отмену,
таймаут и игнорирование поздних ответов. Владелец самостоятельного контроллера отвечает
за его уничтожение. Преобразование заканчивается до записи, исключая частичную запись
при ошибке парсера, подготовки URL или сериализатора.
